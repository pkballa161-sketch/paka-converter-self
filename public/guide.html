Converter Setup guide

run it yourself

Self-hosting

No credits, no API key, no monthly ceiling. You run the converter, so the only limit is your own machine — and the only cost is what that machine costs, which can be nothing.

Because ffmpeg runs on your machine, this edition can genuinely build containers the paid services refuse: MP3, M4A, AAC, FLAC, WAV, OGG, Opus, AIFF for audio, and MP4, MOV, MKV, WEBM, AVI or even GIF for video.

What you're actually running

Three parts, and only the middle one is new:

  1. This page, which reads the video and shows the download card. It's already hosted for you.
  2. A small Node script, server/server.mjs, that calls yt-dlp and ffmpeg to fetch and convert the file.
  3. The machine that script runs on — your own server.

Step 1 — get a machine

Two options that cost nothing:

Oracle Cloud Always Free best

2 Arm cores, 12 GB RAM, 200 GB storage, 10 TB of traffic a month, free for the life of the account. A card is required to verify you but is not charged. Capacity in your home region can be temporarily full, which is the usual snag.

Render no card

A free Docker web service: 750 hours a month, no payment details at any point. It sleeps after 15 minutes without visitors and takes about a minute to wake. Its 512 MB of RAM is comfortable for audio but can struggle with long video conversions.

Oracle is the one that behaves like a real server. Render is the one that asks for no card at all.

The no-card route, in full

Render needs your two files to live in a place it can read, so GitHub holds them. Both accounts are free and neither wants a card.

  1. Make a free account at github.com, then create a repository — public, any name.
  2. In that repository click Add file → Upload files and upload Dockerfile and server.mjs. Both go at the top level, no folder.
  3. Make a free account at render.com using “Sign in with GitHub”. No card, no billing page.
  4. Click New → Web Service, choose that repository, set Language: Docker, and pick the Free instance type. Leave everything else alone.
  5. Wait for the build to finish. Render gives you an address like https://pake.onrender.com. That, with /api/convert on the end, is what this site needs.

Two honest caveats. Render sleeps after a quarter of an hour with no visitors, so the first conversion of a session makes you wait about a minute while it wakes — pressing the button again is enough, and a free service like cron-job.org can ping it every ten minutes to keep it awake inside your 750-hour allowance. And free hosts sit in data centres, which YouTube treats with suspicion: expect the occasional “confirm you're not a bot” refusal on YouTube specifically, fixed by the cookie trick below, with TikTok and Instagram unaffected.

A note on Hugging Face Spaces: their Docker Spaces used to be free and no longer are — as of 2026 you need a paid plan to create one, so ignore any older advice that points you there.

Step 2 — install the two tools it drives

If you're doing this from a phone, every server provider has a web terminal in its dashboard — you can paste these same commands there.

On a fresh Ubuntu server:

sudo apt update
sudo apt install -y ffmpeg python3-pip pipx nodejs npm
pipx ensurepath
pipx install yt-dlp

Check both answer before going further:

yt-dlp --version
ffmpeg -version

Step 3 — put the converter on the server

The whole converter is one file, and you can pull it straight onto the server from this page:

mkdir -p ~/converter && cd ~/converter
curl -O https://site-f0338d6656e64b209659f11b3a53d21f.freebuff.page/server.mjs
CONVERT_API_KEY=change-me node server.mjs

Prefer to move it yourself? Download server.mjs and copy it into ~/converter.

It answers http://localhost:8080. Keep the CONVERT_API_KEY value — it stops strangers using your bandwidth once the port is public.

Step 4 — open the port

On Oracle that means two places, and missing one is the classic mistake:

  1. The cloud firewall: in the Oracle console, your instance's subnet → Security List → add an ingress rule for TCP port 8080 from 0.0.0.0/0.
  2. The server's own firewall: sudo ufw allow 8080/tcp.

Then from your phone's browser open http://your-server-ip:8080/health and you should see {"ok":true}. If you don't, it's nearly always the security list.

Step 5 — point this site at it

Add these two settings to this site and redeploy:

CONVERT_API_URL=http://your-server-ip:8080/api/convert
CONVERT_API_KEY=change-me

The key must match the one the server started with. That's the whole connection — the Convert button now produces real files, with nothing per-download.

Step 6 — keep it running

A process started by hand dies when you close the session. A systemd unit keeps it alive and restarts it after a reboot:

sudo tee /etc/systemd/system/converter.service >/dev/null <<'EOF'
[Unit]
Description=Tube2MP3 converter
After=network.target

[Service]
WorkingDirectory=/home/ubuntu/converter
Environment=PORT=8080
Environment=CONVERT_API_KEY=change-me
ExecStart=/usr/bin/node server.mjs
Restart=always

[Install]
WantedBy=multi-user.target
EOF

sudo systemctl enable --now converter
sudo systemctl status converter

The part that actually bites

YouTube, TikTok and Instagram all treat datacentre addresses with suspicion, so your server will sometimes answer with “Sign in to confirm you're not a bot” or “unexpected response from webpage request”. That is exactly why paid APIs exist. The fix is cookies: they make yt-dlp look like a visitor who is already signed in.

You need the cookies exported once, from any browser where you're signed in to the site that's refusing you. Install a “Get cookies.txt LOCALLY” extension, open the site while signed in, export, and you get a file of plain text.

Putting them on Render

  1. Open the cookie file on your phone and copy all the text.
  2. Paste it into the box below and press the button. It gives you one long line of letters.
  3. In Render, open your service → Environment → Add Environment Variable. Key: COOKIES_B64. Value: the line you just copied.
  4. Save. Render restarts by itself, and /health will now say "cookies": true.

The encoding happens in your browser — the text is never uploaded anywhere. Cookies expire after a few weeks to months; when downloads start refusing again, export a fresh file and repeat.

On a server you manage yourself

Either set COOKIES_TXT to the file's contents, or drop the file next to the script and set COOKIES_FILE=/path/cookies.txt.

If it still refuses, pipx upgrade yt-dlp — upstream usually fixes new walls within days.

If it still doesn't work

The site says "one step left"

CONVERT_API_URL isn't set on the site, or the last deploy didn't happen after you set it. Set it, redeploy, reload.

My converter can't be reached

Open http://your-ip:8080/health from outside the server. Nothing? It's the firewall — usually the Oracle security list, not ufw. Something? Check the URL ends in /api/convert.

Conversions fail with a bot message

See the section above: add cookies, then restart. If cookies are already set, they've expired — export a fresh file.

Long videos fail on Render

512 MB isn't enough to merge a long 1080p video. Either pick 360p/MP3 for long ones, or move to Oracle or a small paid VPS.
